# V6.13-P1B2-R2 — P1-A inside the deterministic deep Rescue (FIXED_N)

Code commit: `perf: enable lazy pallet metrics in deterministic deep Rescue`, on top of `8f55c14` (R1).
Scope: **P1-A (deferred pallet metrics + `_area_union_xy` memo) enabled only inside the FIXED_N deep-path Rescue.** Rescue termination conditions, search order, candidate order, budgets, heuristics and scoring are unchanged. Repair, Exact, Global, the OPEN probes and B3 are untouched.

## 1. What changed

* `RelojTrabajoConWatchdog.permite_p1a`: `False` (R1) → `True` (`src/medidor_trabajo.py`). That is the whole functional change: the P1-A gate in `_resolver_pallets_backtracking` already honoured the flag.
* Rationale: since R1 the Rescue no longer depends on CPU time to decide how much work it does (it ends by `solucion` / `sin_progreso`). Making each node cheaper cannot make it explore more; it can only make it finish sooner. Repair/Exact/Global stay CPU-governed and keep P1-A off for the opposite reason.
* Comments/docstrings updated in `src/packing_bloques.py` and `src/rescue_solver.py`; no logic change there.
* Tests (`tests/test_p1b2r1_rescue_natural_exhaustion.py`, now 23 tests): P1-A assertions inverted to ON; new `test_p1a_en_el_rescue_no_cambia_trabajo_motivo_ni_resultado` (parametrized: work count, stop reason and result identical with and without P1-A) and `test_el_rescue_usa_realmente_las_metricas_diferidas`.
